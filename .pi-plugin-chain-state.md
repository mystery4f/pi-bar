## Phase 1 — spec
**Shape**: Three-row footer bar via `ctx.ui.setFooter`, rendered once per frame from a `Snapshot`.
Rows have fixed roles — `working` (activity, model, thinking, context), `place` (cwd, git),
`reported` (status keys, commands); a row with nothing to show is dropped. Row one is drawn as
filled cells, rows two and three as flat text with a hairline separator, and each row runs its
own collapse ladder. Closed set of eight segment types: `model`, `context`, `cwd`, `git`,
`activity`, `status`, `command`, `value`. Children: nothing nested — a `status` segment may claim
one key or `*` for the unclaimed rest; segments never contain segments. Config: single TOML file
at `~/.pi/pi-bar/config.toml` with `[colors]`, `[bar]` (separators, options) and
`[[bar.segments]]`. Two fields carry expressions (`when`, `eval`). No tools are registered;
this is a UI extension only.

**Decisions**:
- ADR-0001 — footer seam through typed `ctx.ui.setFooter`; rejected `setStatus`-only, `setWidget`, `ctx.ui.custom`.
- ADR-0002 — TOML via `smol-toml`; rejected the 789-line hand-written parser, JSON, TS config.
- ADR-0003 — branch from `footerData.getGitBranch()`, dirtiness from one debounced `git status --porcelain=v2`; rejected own fs watchers.
- ADR-0004 — collapse ladder as the only width strategy; rejected truncation and wrapping.
- ADR-0005 — `ctx.ui.setStatus` is the only extension point; rejected a module registry (duplicate package instances).
- ADR-0006 — single expression language (`when`, `eval`); rejected four per-type eval fields and a vm sandbox.
- ADR-0007 — three rows with fixed roles and per-row weight (block for `working`, flat for the quiet rows); overturned the Phase 1 "one row" assumption after the prototype showed the footer is a flex child that can carry several lines.

**Tickets**: T1 bar appears (no blockers) → T2 configurable → {T3 narrow terminal, T4 context, T6 activity/status}; T3 → T5 cwd/git; T6 → T7 command/expressions. Published in `docs/tickets.md`; not yet filed as GitHub issues.
